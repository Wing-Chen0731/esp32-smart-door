蜂鸣器 PWM 提示音

仅展示逻辑状态，不播放电脑声音

PWM 用快速开关形成方波；频率影响无源蜂鸣器音调。此模块展示频率参数与运行日志，真实声音需由实际蜂鸣器产生。

按键为什么需要防抖

理想按键HIGH ─────┐　　 ┌───── HIGH
　　　　└─────┘
机械触点抖动HIGH ──┐┌┐┌┐── HIGH
　　　└┘└┘└┘

触点在几毫秒内多次接通、断开。程序等待输入稳定约 50 ms，再确认一次按下沿；不做防抖时，一次按键可能被读成多次。

INPUT_PULLUP松开时读 HIGH，按下接地读 LOW；避免引脚悬空乱跳。
边沿检测只在 HIGH→LOW 的稳定变化触发一次，不因按住而重复触发。
millis 思路记录变化时刻并在主循环检查时间差，不用长 delay 阻塞其他任务。
职场应用按键、限位开关、继电器输入都要处理抖动、超时与重复事件。

SPI、UART、I²C 怎么选

协议本项目用途典型取舍
SPIMFRC522 读卡速度高、需多根信号线和片选
UART命令与日志点对点、接电脑简单
I²C可扩展 RTC / 传感器两根总线可挂多个低速设备

协议不是背诵题：结合速率、线数、设备数量、平台支持和调试成本来选。

通信流程

STA（站点模式）设备主动加入网络；此处用 Wi‑Fi 连接状态开关演示。
发布 / 订阅门禁将状态发到主题；远程命令由订阅者接收。
QoS 0 / 1状态允许偶尔丢失；事件和报警按至少一次语义演示，可能重复。
Retained新订阅者可读到最近保留状态；LWT 异常离线时更新为 offline。
非阻塞重连断连时本地按键照常工作；恢复连接后重新订阅并上报状态。
建议主题smartdoor/status · event · command · alarm · lwt

故障诊断流程

RFID 读卡器故障模拟连续三次健康检查失败 → FAULT；刷卡不可用，但本地出门按钮仍可用。
门磁防拆已上锁时传感器报告开门 → TAMPER 并发布报警；关门后才能 CLEAR。
看门狗模拟主循环停滞、监督超时与安全复位；硬件复位原因需真实芯片验证。
内存监测展示模型中的“固件堆”计数；它不是本机进程 RSS 或 ESP32 实测值。

真实硬件需要验证的内容

此面板不模拟 GPIO 电平、电源噪声、实际 RFID/Wiegand/OSDP、电气信号完整性、芯片功耗，也不能证明真实 72 小时稳定性。相关说明中的电阻、电容、布线和低功耗数值应视作待验证参数，须依据所选硬件数据手册与实测确认。真实深睡时 Wi‑Fi/MQTT 连接不会保持；唤醒后需要重新连接。

可观察的系统状态

NORMAL授权卡、出门按钮和 MQTT 命令可按权限开门。
TAMPER锁定期间检测到门开；阻止远程控制，关门后 CLEAR。
FAULTRFID 子系统异常；拒绝刷卡，但保留本地出门操作。
恢复顺序先恢复传感器或读卡器，再复位告警；检查日志和状态上报。
